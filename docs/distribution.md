# Installing and packaging Vauss

`vauss` is a single Rust executable per platform. It has no Python runtime dependency. GPU drivers come
from your system; every other helper is either bundled in the release archive or downloaded on first use
from a pinned, hash-checked URL.

## Release archives

Each [GitHub release](https://github.com/voyager-so/vauss/releases) has one archive per platform plus a
`.sha256` sidecar:

| Platform | Target | Archive | Needs |
|---|---|---|---|
| Linux x64 | `x86_64-unknown-linux-gnu` | `.tar.gz` | glibc 2.35+ (Ubuntu 22.04 or newer), Vulkan driver |
| macOS Apple Silicon | `aarch64-apple-darwin` | `.tar.gz` | macOS 11+ |
| Windows x64 | `x86_64-pc-windows-msvc` | `.zip` | Windows 10+, Vulkan or DX12 driver |

An archive holds the `vauss` executable (with `splat` and `voyager-splat` compatibility aliases) and a `tools/` folder beside it, so a fresh install works offline:

| Bundled helper | Used for | License |
|---|---|---|
| FFmpeg + ffprobe: our own static LGPL 8.0.3 build, no x264/x265 ([dist/ffmpeg/](../dist/ffmpeg/README.md); binaries and complete source on the `ffmpeg-public-v3` release) | Reading video, extracting frames, writing shot videos | LGPL-2.1-or-later |
| COLMAP 4.2.1 (Linux: our CPU-only build, see [distribution-colmap.md](distribution-colmap.md)) | Camera poses (structure from motion) | BSD-3-Clause plus bundled library notices |
| ONNX Runtime 1.28 (CPU) | LPIPS scoring, segmentation models | MIT |
| LPIPS AlexNet / VGG (ONNX) | Perceptual quality scores on held-out frames | BSD-2 / BSD-3 / Apache-2.0 |
| gltfpack 1.3 | Compressing exported meshes | MIT (+ Apache-2.0, BSD-3 parts) |

On macOS and Windows, COLMAP is the official upstream release, downloaded on first use. The archive also
contains `THIRD_PARTY_LICENSES.txt` (every Rust dependency, generated by `cargo-about`), `NOTICE.txt` (all
third-party attributions, including Brush), this file and `assets.json`.

Archives are not code-signed or notarized yet. On macOS, clear the quarantine flag after unpacking
(`xattr -dr com.apple.quarantine <folder>`) or allow the binary in System Settings → Privacy & Security.

## Install

```sh
# Linux / macOS: read the script first; pass an explicit version (the release tag without "vauss-v")
sh scripts/install.sh 0.1.20-rc
```

```powershell
# Windows
./scripts/install.ps1 -Version 0.1.20-rc
```

The installers download the archive, check it against its SHA-256 sidecar, and need no admin rights. On
Linux and macOS the release goes to `~/.local/share/vauss/<version>/`, with `vauss`, `splat` and
`voyager-splat` links in `~/.local/bin` (add that directory to your `PATH`). Windows installs into
`%LOCALAPPDATA%\vauss\bin`. `VAUSS_INSTALL_DIR` / `-InstallDir` change the executable location;
`VAUSS_RELEASE_BASE_URL` points at a mirror. The older `SPLAT_` installer variables remain supported.

You can also unpack an archive anywhere by hand and run `vauss` from that folder: keep `tools/` next to it.

## Build from source

You need a recent stable Rust toolchain (edition 2024) and, on Linux, a Vulkan loader
(`libvulkan1`). Standalone viewer templates are included in the Rust source; Node and pnpm
are not required to build the CLI. Node is needed only for optional SOG export.

```sh
cargo build --locked --release -p splat-cli    # binary: target/release/vauss
target/release/vauss doctor
```

A source build has no `tools/` folder, so helpers download on first use into the cache (below). `vauss fetch
<asset>` downloads one ahead of time, for example `vauss fetch colmap`.

## Helper downloads and the cache

[`crates/splat-fetch/assets.json`](../crates/splat-fetch/assets.json) lists every helper and model splat
may download: exact HTTPS URL, version, SHA-256, size, license and source. There are no moving `latest`
URLs. Downloads are hashed before they are unpacked, unpacked into a temporary folder, and moved into the
cache only when complete; a damaged cache entry is never reused. splat looks for a helper in this order:
an explicit setting (config file or environment variable such as `SPLAT_COLMAP`), the bundled `tools/`
folder, the cache, and finally a download.

Cache location: `SPLAT_CACHE_DIR` if set, otherwise `$XDG_CACHE_HOME/splat` or `~/.cache/splat` on Linux,
`~/Library/Caches/splat` on macOS and `%LOCALAPPDATA%\splat\cache` on Windows. Old versions can be deleted
when no splat process is running.

Optional downloads that are never bundled:

| Asset | Used by | License |
|---|---|---|
| SAM 2.1 (GGML) and Grounding DINO Tiny | Selecting objects by name (`select_objects`, `mask_distractors`, "remove the …" goals), run through the Spirula helper below | Apache-2.0 |
| Depth Anything 3 Base | Learned camera fallback and dense initialisation | Apache-2.0 |
| COLMAP vocabulary trees | Loop closure on long videos | BSD-3-Clause |
| LaMa, Depth Anything v2 Small, Stable Diffusion 1.5 inpainting (ONNX) | `inpaint_removed` (filling holes after removing an object) | Apache-2.0; SD 1.5 is CreativeML OpenRAIL-M, which carries use restrictions |
| Spirula 2026.10.6 | The object segmenter above and the optional `spirula` engine. Never downloaded automatically: opt in with `vauss fetch spirula --allow-gpl` or `SPLAT_ALLOW_GPL=1`. Needs `libopengl0` on Debian/Ubuntu | GPL-3.0, run as a separate program, never linked or bundled ([statement](provenance/spirula-clean-room.md)) |

## Licenses of what splat runs

- Original Vauss code uses the source-available [Vauss Preview License](../LICENSE).
  Separately licensed components retain their original terms: Brush-derived `crates/splat-train*`
  remain Apache-2.0, and vendored CubeCL remains MIT OR Apache-2.0. See the root license
  and [`NOTICE`](../NOTICE) for the complete component scope and retained licenses.
- The top-level [`deny.toml`](../deny.toml) (`cargo deny check licenses bans sources`) allows permissive licenses
  and MPL-2.0 for linked Rust dependencies, never GPL, AGPL or LGPL. `scripts/licenses.sh` generates the full inventory and fails if a license cannot be resolved.
- FFmpeg, COLMAP, gltfpack and Spirula run as separate executables. The FFmpeg build reports
  LGPL-2.1-or-later with GPL, nonfree and version3 components disabled, so `-c:v libx264` is not available;
  splat writes videos with the encoders that build provides.
- Model licenses are separate from code licenses. Each downloaded model keeps its notices in its cache folder.

## Building release archives

```sh
cargo install cargo-about --version 0.9.2 --locked --features cli
scripts/package.sh x86_64-unknown-linux-gnu ./dist-out      # Windows: ./scripts/package.ps1
```

`package.sh` builds `splat-cli` from `Cargo.lock`, stages the bundled helpers with `scripts/bundle-tools.sh`,
writes the license inventory, and produces the archive and its checksum.
The maintainer release pipeline builds these archives natively for all three targets from the public source snapshot, then publishes them as a GitHub release.
A pre-release tag such as `vauss-v0.1.20-rc` creates a visible prerelease, never marked Latest.
Platform archives are attached individually after their builds, smoke checks and payload scans pass;
the release notes identify whether builds are still in progress. Each platform unpacks its archive and
checks that `vauss doctor` reports every bundled helper ready with an empty cache and no network
(`scripts/check-bundled-doctor.sh`).

The separate full Windows pipeline proof uses a clean, GPU-less runner and the WARP software adapter. As of Oct 24, 2026, it had **not been verified on the current main**: the last attempt was cancelled after about 1 h 50 min without a result. Archive builds and bundled-tool smoke tests are separate from that full reconstruction proof.

Before a production release, macOS archives should be signed with a Developer ID and notarized, and the
Windows executable signed with an Authenticode certificate. Neither is set up yet.

## Optional hosted workflows

Local reconstruction, training, evaluation and export do not require fal.ai or an API key.
Hosted generation features are optional: set `FAL_KEY` explicitly when using them and review
the selected provider's pricing and model terms. No account credentials are bundled.
